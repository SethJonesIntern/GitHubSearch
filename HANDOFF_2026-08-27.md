### The scope definition, settled 2026-08-27 — do not re-litigate

> An **agentic application** is one that **imports an agentic framework**.

It is *not* "an LLM application". A repo reaching a model only through a raw provider SDK
(`openai`, `anthropic`, `ollama`, `litellm`) or raw HTTP is **out of scope** — Stage 2 only
ever searched framework import names, so such a repo was never sampled deliberately and can
only have arrived by a token collision.

**This does not change counting inside in-scope apps.** Raw-SDK calls made by an agentic
application stay measured; the share of call sites that bypass the framework is a finding
in its own right (figure Q3). EXCLUSIONS §17 states this.

### The verification rule that matters most

> A matched token is a **collision** only when the clone **does not import it**. Check
> `frameworks.csv` (the Stage-1 discovery set) before cutting on that basis.

It saved two repos this session: `IBM/ares` genuinely imports `deepteam` (3 files) and
`fetchai/fetchai` imports `uagents_core` (19 files) — both Stage-1 discovered frameworks.
It also confirmed cutting `nottelabs/bua`: notte's discovered import names are
`notte; notte_agent; notte_browser; notte_core; notte_eva…`, and `notte_sdk` (a hosted
browser client used beside `browserbase`) is not among them.

`imports_matched_fw` in the audit sheet is this check, already computed — but only for rows
where `zero_invoker == "1"` (see H4c).

## 2. Work queue — desktop only, in value order

### H4. Fix `shallow_clone` — highest value/effort in the project
**Worth ~20 in-scope repos whose source is already on disk.**

22 repos never processed. They are **not** deleted from GitHub — `git ls-remote` confirms
17 of 20 alive. The real cause is a Windows filename bug:

```
error: unable to create file .../generated_results_2025-07-10_16:17:30.jsonl: Invalid argument
fatal: unable to checkout working tree
warning: Clone succeeded, but checkout failed.
```

A `:` in a filename. Git fetches every object, the checkout aborts, `git clone` exits
non-zero, and `transitive_invokers.shallow_clone` (line 58) returns `False`. The driver
records `{"stage": "clone"}` and skips analysis.

**The tree is substantially there.** Reproduced on `Azure/plan-search-chatbot`: 157 files
checked out including **all 36 `.py` files**, matching `py_files=36` in the sheet. Only the
one illegal `.jsonl` was lost.

**Fix:** in `shallow_clone`, treat a non-zero exit as *partial success* when the tree exists
and contains `.py` files — catch `CalledProcessError`, test the tree, log a warning, return
`True`, record the repo as `clone_partial` so it stays auditable. Keep returning `False` for
genuine failures (auth, 404, timeout). Then re-queue.

⚠️ **`batch_call_metadata` `shutil.rmtree`s the checkout before cloning.** Do not re-queue
these before the fix is in, or a hard failure after deletion loses source we currently have.
It has not bitten yet only because the clones do partially succeed.

Genuinely gone from GitHub (no checkout, `ls-remote` fails): `agno-agi/pal`,
`holetron/hindsight-mempalace`, `openJiuwen-ai/agent-store`.

### H4b. The `biliVideo` detector gap

### H4d. Missing framework registry names

discovered frameworks that are not keys in `FRAMEWORK_CALLS`**. No patterns fire for them,
and `audit_imports`'s `KNOWN`-limited regex cannot see them — `fetchai/fetchai` imports
`uagents_core` in 19 files and still looked raw-SDK-only.

full gap. **`notte_sdk` is NOT such a case** — it is Notte's hosted-browser client, absent

## 3. What happened on 2026-08-27 (so a cold context has the reasoning)

115 repos cut across four new ledger sections. **281 of the 302 repos dropped from the
population are now documented cuts; only 21 are accidental** (the clone bug). Token
collisions alone are over half of everything removed.

- **§14** Queue A — 9 `clai` collision survivors. **No repo in the corpus imports `clai`**
  (grep over all 49 matched clones). `clai` *is* pydantic-ai's CLI package, but code search
  matched the substring in **claim / claims / claimed / disclaimer**: `claim_line_item_id`
  (medical billing), `claimtoken` (auth), `claimed_index` (a job queue).
- **§15** *framework imported for a non-invocation purpose* — a new, reusable criterion.
  The name is real and the import is real, but it registers a handler, declares a tool the
  **host's** model may call, or pulls in a non-LLM utility. 9 AstrBot plugins; four register
  `@llm_tool` handlers, which makes them **callees** of a model, never callers — so zero call
  sites is correct, not a detection miss.
- **§16** Queue B — 59 collisions. `camel`→camelCase (26), `notte`→`@nottest` (12),
  `agno`→agnostic (8), `swarms`→particle/drone swarms (9), `patchwork`→email patch
  workflows (5), `dynamiq`→`dynamiqs` the quantum library (3). Cuts include `getmoto/moto`
  (8,555★), `rasbt/mlxtend` (5,152★), `Pylons/pyramid`, `mongodb/motor`.
- **§17** the scope correction plus 34 raw-SDK-only repos removed from `uncovered`.

**A trap that caught me twice — don't repeat it.** I twice argued from a "contradiction"
between `invokers_direct > 0` and a raw-SDK-only `frameworks_imported`. There is no
contradiction: `openai` and `anthropic` are themselves keys in `FRAMEWORK_CALLS`, so their
patterns fire and a raw-SDK-only repo *should* have invokers. Checking the `reason` column
of `llm_invokers_all.csv` showed all 20 such repos had invokers from `openai`/`anthropic`
patterns and nothing else.

`slice_status` from `os.scandir(SLICES_DIR)` and will blank it for ~780 repos. Safe here on
the PC.

**Conventions.** `py -3.14` always. `PYTHONIOENCODING=utf-8` before `analyze.py` or it can
die on a non-ASCII repo description. Cuts are filters, never deletions — a cut repo keeps
its row and its raw data. Every cut gets a dated row in `EXCLUSIONS.md`. Evidence before
cutting: read the actual matched code, because inference has been wrong repeatedly
(omnigent, connectonion, haystack, clai, and this session `notte_sdk` and `deepteam`).
