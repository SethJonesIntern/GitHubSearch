## The decision (made 2026-09-15, settled — do not re-litigate)

> **We use pyMethods2Test.** Focal mapping comes from the published tool, not from our own
> `pipeline/focal_map.py`.

`focal_map.py` was written first and ran to completion, but it matches only **26.5%** of tests
to a focal callable, and a third of those come from its weakest rung. pyMethods2Test is
published, peer-reviewed, Apache-2.0, ships runnable tooling, and reads what each test actually
calls — which `focal_map.py` deliberately does not do.

## 1. pyMethods2Test

Abdelmadjid & Dyer, MSR 2025. arXiv:2502.05143. **Zenodo record `14264519`** — not `...18`,
which is the concept DOI and 404s on file fetches. **Apache 2.0**, so vendoring it into the
repo is fine with attribution.

Verified working on our clones this session. Two scripts, no network, no cloning:

```
py -3.14 test_identification.py --outfile <impl>.json --outtests <tests>.json <repo_path>
py -3.14 find_focals.py <impl>.json <tests>.json -outfile <out>.focal.json
```

Re-fetch (last session's scratchpad is gone):

```
B=https://zenodo.org/api/records/14264519/files
for f in find_focals.py get_context.py test_identification.py requirements.txt README.md; do
  curl -sSL -o "$f" "$B/$f/content"; done
```

`focal-data.zip` (108 MB) is their pre-mined mapping across 88,846 projects. `raw-data.zip`
is 3.9 GB and is only the intermediate extraction.

**How it works** — read off their source, not the paper (the paper's HTML summary was wrong):

| stage | rule |
|---|---|
| focal file | every source file whose module name the test **imports**; if none, basename-suffix match; if several, basename-suffix then `fuzz.ratio` on basenames |
| focal method | the **invocations in the test body** — test name ends with a called name; else `fuzz.ratio > 50` against the called names |
| focal class | first called method whose last segment is a class in the focal file |
| skipped | any test with zero `called_methods` (`find_focals.py:104`) |

Its method-level output therefore splits into exact-rule matches and `fuzz.ratio > 50`
fallback matches. The threshold is permissive by construction.

**Measured on `NForce-ai_SDRbot`:** 17 of 21 test files got a focal file; **37 of 202 test
methods (18.3%)** got a focal method. On the same repo `focal_map.py` got 15 of 276 (5.4%),
all via its weakest rung. Denominators differ (their 202 test methods in `test_*.py` vs our
276 ND-test rows), so it is directional, not exact.

## 2. The build task

`pipeline/pym2t_focal.py`: drive both scripts over **all 644 observed apps**, then join the
output to the 9,700 ND tests on (test file, method name) — their JSON is keyed that way.

Run on 644, not 233. 233 is our direct-invoker set; their tool has no notion of direct vs
transitive, and per-repo it maps every test regardless, so narrowing to our ND tests afterward
costs nothing. Skipping repos is the only irreversible choice.

Known snag: their `focal_file` comes back as an absolute mixed-separator path when the repo
path passed in is absolute. Normalize to repo-relative before joining.

## 4. Environment gotcha

`find_focals.py` needs `fuzzywuzzy`. Their pinned `python-Levenshtein~=0.26.1` **has no cp314
wheel and fails to build** (`metadata-generation-failed`). The modern package works and is what
`fuzzywuzzy/StringMatcher.py` actually imports:

```
py -3.14 -m pip install "fuzzywuzzy~=0.18.0" Levenshtein
```

Already installed on the PC. Verify the backend before trusting any number:
`fuzzywuzzy.fuzz.SequenceMatcher.__module__` must be `fuzzywuzzy.StringMatcher`. If it reads
`difflib`, the C extension is missing and `fuzz.ratio` silently switches to a different
algorithm, moving every value against their `> 50` cutoff.

We deviate from their pinned `requirements.txt`; that belongs in the methodology.
