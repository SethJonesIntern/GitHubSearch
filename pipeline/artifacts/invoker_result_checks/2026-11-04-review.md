# Review of the first invoker-result/check candidate pass

Measured 2026-11-04 using the saved baseline and slices. This note supplements, and does not replace, the generated 2026-11-04-v1 outputs.

## Findings

The common saved production-method baseline contains 7,642 LLM-containing methods. Of these, 220 have mapped tests, 1,225 have any file association (16.03%), and 1,026 have an import-based file association (13.43%). These are correspondence measures, not validated testing bounds.

The first-pass local analyzer found test-side result-to-assertion candidates for 105/7,642 methods (1.37%), or 105/220 mapped methods (47.73%), in 52 repositories. There are 366 candidate assertion rows across 189/461 method/test links. All 461 test definitions and all 7,642 baseline method definitions were located and parsed; 39 test links were ambiguous at the seed-call line. Source availability is different from analysis completeness.

Separately, the saved baseline labels 38 methods as production methods with local invocation-result assertion candidates (65 rows). Of these, 34 methods in 8 repositories have a call and assertion sharing a saved Joern slice (47 rows). No method has both a detected test-side candidate and a production-side shared-slice candidate. Thus this pass does not establish a joined cross-method invocation-result-to-test-assertion dependence chain.

Exact-only mapping sensitivity gives 30 methods with test-side candidates, compared with 59 methods having an exact mapping. It does not validate dispatch, execution, or checked semantics.

## Classification finding requiring review

21 of the 38 production-labelled candidate methods are actually test_* definitions in XAIHT/Tlamatini, Tlamatini/agent/tests.py. Their enclosing classes inherit TestCase, as confirmed in the original source: LoadedContextFallbackTests (line 619), ExecReportCaptureTests (780), NotificationDebtGuardTests (1210), AskRagMultiTurnTests (2127), LoadedContextPriorityTests (6089), AskExecsExecutorGateTests (6750), and AskExecsChainPropagationTests (7045).

18 of these 21 have shared-slice candidates. The inherited classifier recognizes test_*.py and *_test.py, plus specified test directory names, and misses this tests.py file. Consequently the raw 38/34 counts must not be presented as production runtime-guardrail prevalence. The remaining candidates have not all been validated as production guardrails either. No rows, scope fields, or existing baseline results were altered or excluded; a classification correction requires a separate reviewed change.

## Bounded source inspection

Sherpa test_planning_succeeds assigns task_planning.execute(...) to plan and asserts len(plan.steps) > 0. Sherpa summary tests compare the returned summary with expected text and check its type, using fake models in the inspected examples. Certora AIComposer's refinement_loop.llm_echo locally asserts isinstance(res, AIMessage) after bound_llm.ainvoke(...). These illustrate distinct associations, not established real-model execution or semantic correctness.

## Limits and provenance

Only supported straight-line local expressions and Python/unittest value assertions are inspected. Unsupported branches, arbitrary validators, state/exception checks, dispatch resolution, and full interprocedural value flow are outside this pass. An undetected candidate is not an unchecked method. Joern shared-slice membership is corroborating context, not a directed dependence proof.
